# Color & Typography

Indiscriminate color use dilutes institutional impact. Sophisticated systems operate under severe chromatic restriction. Typography is the most prominent visual element users interact with—and the silent foundation of brand voice.

## Color Engineering

### Hierarchy model

Adopt a relentless hierarchical structure:

1. **Refined neutrals as the base** — from polar white to deep charcoal so focus stays on product and content
2. **Spatial proportions** — adapt 60-30-10 into a stricter split, e.g.:
   - **80%** neutral / negative space
   - **15%** secondary structural elements
   - **≤5%** accent color to guide attention
3. **One primary action color** — reserved for CTAs and isolated highlight moments; **forbidden** as body-text color
4. **One secondary** (optional) — supporting structure only
5. **Semantic feedback colors** — success green, destructive/error red, warning amber; standardized to **WCAG AAA** contrast where feasible; never rely on hue alone (color-blind safety)

### Accent restraint

A vibrant accent, if used, must appear **with extreme sparseness**—for support, assurance, and delight at critical interaction moments—not as ambient fill.

### Accessibility rule

If a pair fails contrast requirements, **do not force approval**. Surgically adjust the color until universal legibility is met. Prefer modular semantic variables over ad-hoc hex picks.

### Suggested token groups

```
color.primary          → CTAs / isolated emphasis only
color.secondary        → structural support
color.accent           → rare highlight moments
color.neutral.0–6      → refined grayscale spectrum
color.feedback.success
color.feedback.danger
color.feedback.warning
color.feedback.info
```

## Typography as Precision Engineering

### Role table

| Designation | Context | Structural rules |
|-------------|---------|------------------|
| **Primary / Display (H1)** | Headlines, advertising, key conversion moments | Fits a rigid mathematical grid. **No** mechanical condensation. **No** false italics generated by software. |
| **Body / Text** | Technical copy, product descriptions, UI reading | Accessibility-aligned; support Dynamic Type. **Leading ≥ 150%** of font size for reading fluency. |
| **Monospace (Technical)** | Hardware specs, numeric IDs, metadata markings | Limited to black, gray, or pure white. Signals precision-engineering heritage in dense data panels. |

### Family discipline

Actively resist a third type family unless a structural use case cannot be met by the two primaries. Random type choices accumulate into visual noise.

### Optical scaling

Prefer families (or optical sizes) that scale cleanly from tiny hardware readouts to large retail panels. Separate **Display** vs **Text** cuts when available; do not use Display for long reading.

## Modular Spacing

Spacing is not a style suggestion—it is a **fixed coordinate** in the brand code.

| Rule | Directive |
|------|-----------|
| Margins, padding, gaps | Must follow a scalar increment system |
| Random values | **Prohibited** |
| Base multiplier example | 4 / 8 / 16 / 24 / 32 / 48 / 64 px (or equivalent rem scale) |

Encode spacing as tokens consumed by UI and layout tools.

## Agent Instructions

1. Build palette from neutrals outward; introduce accent last and sparsely.
2. Assign every color a semantic job; ban decorative free use of primary.
3. Fix type to roles (Display / Text / Mono); ban false italics and forced distortion.
4. Set body leading floor at 150%.
5. Tokenize spacing on a single base grid; reject one-off pixel values in reviews.
